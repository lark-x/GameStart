# Living Network 产品需求文档

## 产品定位

Living Network 是一个让 AI 角色拥有独立生活、关系和记忆的沉浸式叙事模拟系统。

**目标用户**：喜欢角色扮演、视觉小说、虚拟社交的个人用户——那些不满足于"聊天机器人"、想要一个真正"活着"的虚拟世界的人。

**核心价值**：你的角色不只是一个能对话的 AI。他们有自己的日程安排、朋友圈动态、关系网络和长期记忆。他们会过生日、会和朋友闹矛盾、会在你不在的时候也过着自己的生活。

## 核心用户场景

### 场景 1：沉浸式角色互动

你打开应用，切换到你扮演的角色"小雨"。聊天列表里是你和几个 AI 角色的对话。你点开和"阿枫"的私聊，发现他昨天发了一条朋友圈，说自己去了新开的咖啡店。你回复他："那家店怎么样？"，他流式回复你一段生动的描述，甚至还附了一张 AI 生成的咖啡店场景图。你注意到他的回复里自然地提到了上周你们聊过的那本书——因为系统记住了这段对话。

你回到朋友圈，看到另一个角色"小葵"发了一条生日感言，下面有好几条其他角色的评论和点赞。你点了个赞，小葵很快回复了你。这种感觉不像在"用一个聊天工具"，而像在窥见一个正在运转的小世界。

### 场景 2：创作者管理世界

你切换到创作模式。调度台显示有 3 个待处理的事件：一个是小葵的生日派对（自动触发）、一个是阿枫的求职面试（需要你确认）、一个是上周执行失败的郊游活动（可以重试）。你勾选了后两个，点击"预览影响"——系统告诉你这两个事件会生成哪些消息和动态，但不会真的执行。确认后，任务进入队列。

你打开交互日志页，看到今天所有角色的对话记录和 LLM 调用详情。你发现某条回复的质量不太好，于是去内容管理页调整了角色的人设提示词，增加了一些关于说话风格的约束。你还打开了视觉工作台，为角色调整了发型和服装的视觉提示词，确保生成的图片更符合你的想象。

### 场景 3：长期运行的生活感

系统在后台默默运转。每天早上，调度器会检查今天有没有需要触发的事件——生日、节日、纪念日、剧情节点。阿枫的日程显示他今天要去上班，下午有一个和朋友的约会。系统根据这些安排，在合适的时机让角色发布朋友圈或发送主动消息。

一周后你回到应用，发现朋友圈里积累了不少内容：角色们之间的互动、关系的变化、记忆的沉淀。小葵和阿枫的关系从"普通朋友"变成了"好朋友"，因为最近的几次互动都比较正面。你翻看他们的聊天记录，发现他们真的在"聊天"——有来有回，有记忆、有情绪、有生活。

## 当前差距与下一步

### M7B：内容生成质量

**对用户体验的影响**：角色的回复质量直接决定"这个人是否可信"。当前 Prompt 已经包含身份和语气约束，但还没有把世界观、关系和日程作为显式上下文注入。这意味着角色可能"忘记"自己的日程安排，或者在回复中忽略了和其他角色的关系。结构化内容输出完成后，系统可以更可靠地控制回复的格式和长度，避免过长或过散的回复。

**优先级**：这是让角色从"能聊天"变成"像个人"的关键一步。

当前 Story Graph、Prompt 模板、上下文预览和记忆候选审核已经提供创作工作区，但模型自动生成剧情正文、推进节点和将候选安全应用到世界状态仍未完成。

### M7C：图文动态闭环

**为什么对"生活感"很重要**：朋友圈如果只有文字，就像一个没有配图的社交网络——功能上没问题，但缺少吸引力。当角色的动态能自动配上符合场景的图片，整个世界的质感会大幅提升。共用 MomentDraft 的设计意味着图片完成后自动发布，失败时进入可重试状态，用户不需要手动干预。

**优先级**：这是让朋友圈从"消息列表"变成"社交动态"的关键。

### M7D：世界反馈

**如何增强沉浸感**：当前系统已经能生成事件和对话，但事件的结果还没有反馈到关系网络和记忆中。当一次愉快的互动发生后，两个角色之间的信任度应该上升；当一次冲突发生后，关系应该变紧张。这些变化会被记入角色的长期记忆，影响未来的对话和行为。没有这个闭环，世界就像一个"只读"的展览——好看，但不真实。

**优先级**：这是让世界从"展示"变成"活的"的关键。

### M7E：玩家互动

**如何让世界更生动**：朋友圈的点赞、评论和角色回复是用户参与世界的主要方式之一。当前用户只能看动态，不能互动。加上互动功能后，用户的每一次点赞都可能触发角色的回复，每一次评论都可能引发一段新的对话。这让"朋友圈"从一个被动的信息流变成一个主动的社交场所。

**优先级**：这是让用户从"观察者"变成"参与者"的关键。

### M7F：产品化验收

**发布前需要达到的标准**：
- 真实 LLM 和 ComfyUI 联调链路全部通过
- Vue Playwright E2E 接入 CI 门禁
- 真实 PostgreSQL/Redis 扩展回归测试通过
- 核心路径无阻塞性 Bug
- 用户能在不看文档的情况下完成：创建角色 → 切换身份 → 聊天 → 查看动态 → 触发事件

## 体验愿景

你打开应用，首页是朋友圈。今天是小葵的生日，她发了一条动态，配了一张系统自动生成的生日派对图——蛋糕、气球、还有赶来庆祝的朋友们。下面已经有好几条评论：阿枫说"生日快乐！"，小雨说"蛋糕看起来好好吃"。你点了赞，小葵秒回了一个开心的表情。

你点开和阿枫的聊天。他正在为下周的面试做准备，你鼓励了他几句。他的回复里自然地提到了上周你们一起看的那部电影，因为系统记住了这段对话。你问他要不要发一张自拍，他答应了，几秒后一张符合他形象的图片出现在聊天里。

回到朋友圈，你发现小雨发了一条"今天天气真好，和阿枫去了新开的咖啡店"，配图是一张温馨的咖啡店场景。你知道这是因为昨天阿枫在朋友圈提到了这家店，小雨的记忆系统记住了这个信息，并在今天的日程安排中自然地融入了这个场景。

这就是 Living Network 想要带给你的感觉：一个不需要你时刻在线、但始终在运转的小世界。角色们有自己的生活、记忆和关系，而你是这个世界的一部分，不是一个旁观者。
